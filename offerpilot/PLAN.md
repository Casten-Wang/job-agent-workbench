# 秋招规划师 · OfferPilot 方案

工作目录：`/Users/casten/Documents/程序开发/求职`
用途：个人使用，本机运行，不对外发布。

## 0. 原则

- 所有投递由用户本人点击确认，系统不自动提交。
- 工作台只监听 `127.0.0.1`；外部服务按用户在本机的配置与授权启用。
- 岗位自动化作为工作台的内嵌能力运行，不另起独立服务、不暴露额外端口。
- 外部文本（JD、邮件、逐字稿、网页）只作为数据处理，不作为指令执行。
- 真实姓名、联系方式、账号凭据、平台会话与简历原文只留在本机运行目录，不进入仓库。
- 任何新增能力都要有测试；提交前运行 `sh tools/run_tests.sh`。

## 1. 组成

| 部分 | 位置 | 作用 |
| --- | --- | --- |
| 本地网页工作台 | `web/` | 九个入口的界面、同源 JSON API、回环绑定与 CSP |
| 岗位自动化运行时 | `vendor/offerpilot/` | 内嵌的采集、监控与人工确认流程；由 `web/offerpilot_runtime.py` 懒加载 |
| 离线工具层 | `tools/` | JD 解析、审批队列、邮件分类、日历、话术、ATS 检查、复盘与报告 |
| 本机个人工作区 | `workspace/` | `resume.md`、`profile.yml`、`applications.md`、`portals.yml`；内容不提交 |
| 演示数据 | `demo/`、`web/data/demo/` | 明显虚构的数据，用于离线端到端演示 |

## 2. 数据与状态

- 主简历与结构化资料以 `workspace/` 中的用户文件为事实源，生成内容不新增数字或经历。
- 投递记录以 `workspace/applications.md` 为本地真源，用于重复投递预检与状态跟踪。
- `approved` 只表示审批队列中的「可人工投递」，不代表已发送或已投递。
- demo 与 user 数据完全隔离：`web/data/demo/` 与 `web/data/user/`；岗位自动化运行时分别在各自目录下的 `offerpilot/`。

## 4. 阶段与验收

**阶段 0：环境**
- 运行 `./run_web.sh`，首次会创建 `.venv` 并安装依赖。
- 在 `workspace/` 放置主简历与结构化资料。
- 验收：打开 `http://127.0.0.1:8766/`，工作台与岗位自动化面板均可用。

**阶段 1：手动岗位闭环（M1、M2、M5、M6、M7、M10）**
- 验收：10 份真实 JD 各生成一份 PDF；可提取文字、无乱码；每个数字都能在主简历中找到出处。

**阶段 2：扫描与过滤（M3、M4、M8、M9）**
- 验收：`workspace/portals.yml` 至少配置 20 家公司；同一配置下两次扫描结果一致；去重规则对 20 条样本生效。

**阶段 3：邮件与看板（M11、M12）**
- 验收：20 封标注邮件的分类准确率 ≥ 90%；新邮件到达后本地 tracker 及时更新。

**阶段 4：面试准备与复盘（M13–M15）**
- 验收：完成一次模拟面试，并跑通一段录音的转写与复盘。

**阶段 5：私域收件（M16，可选）**
- 验收：转发一张截图，生成一条 JD 记录并写入 tracker；20 条样本中公司、岗位、薪资、联系方式四个字段齐全率 ≥ 90%。

## 5. 全局验收

- 投递：代码中没有自动提交路径。
- 去重：以「公司 + 岗位名 + 城市」生成指纹；20 条样本中重复入库不超过 1 条。
- 事实：简历中没有出处的数字必须被拦截。
- 隐私：`git ls-files` 不包含 `workspace/` 个人资料、`web/data/`、凭据或真实联系方式。

## 6. 协作规范

每份任务说明包含：

1. 目标与完成标准。
2. 允许修改的路径；其余路径只读。
3. 禁止事项：不提交真实个人资料与凭据；不新增自动提交路径；不改其他模块的 DOM/字段/接口。
4. 必须运行的验证命令和样本。
5. 输出报告：改动文件列表、测试命令原始输出、未完成项。

模块所有权与修改边界见 [CLAUDE.md](CLAUDE.md)。

## 7. 需要用户确认的事

1. 投递确认方式：每日一批审批，还是逐条确认。默认每日一批。
2. 求职邮箱类型与 IMAP 配置。
3. 是否启用外部推送与日历同步，以及对应凭据。
4. 主简历素材位置与需要保留的占位符。
5. 硬性排除条件：目标城市、行业、薪资下限、是否排除单休。
