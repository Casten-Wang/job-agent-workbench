# 单条面经收藏与更新订阅

实现入口在 `interview_agent/xhs_notes.py`、`note_subscriptions.py` 和 `note_api.py`。功能接在个人 Career Agent 的生命周期内，通过既有同源桥接提供给工作台。沿用本机 Bearer 鉴权、固定 owner 与 user/demo 隔离；demo 不启用采集。

## 在 Agent 使用

启动更新后的完整个人 Agent，刷新工作台，选择“我的 user”。在 Agent 输入以下命令；链接位置替换成自己明确提供的小红书单条笔记链接：

```text
/面经
/面经收藏 链接
/面经订阅 链接 24 Python,后端
/面经订阅列表
/面经暂停 sub_编号
/面经恢复 sub_编号
/面经消息
/面经查看 note_编号
/面经已读 msg_编号
/面经自检
```

订阅周期为整数小时，默认 24，允许 1 至 168。关键词可省略，最多十个，用逗号分隔；忽略大小写，标题与正文中命中任意一个即满足。首次成功且命中条件会通知，之后只通知未出现过的内容版本。未命中的成功内容仍保存，便于追溯。相同订阅的同一版本恢复到旧内容时也不重复通知。

同 URL、同配置重复创建返回已有订阅。修改配置需先暂停，再用同一 URL 和新配置创建，会沿用编号并启用。相同配置不会自动恢复暂停任务，需显式 `/面经恢复`。恢复会立即安排一次检查。

Agent 对 `/面经` 命令走确定性分支，无需模型判断链接、调度周期或触发条件。原始链接及收藏正文不会作为这次命令的模型输入；它们仍保存在本机记录与会话中。收件箱原文使用文本节点显示，来源链接保留查询串，并设置不发送 Referer。默认不自动请求笔记图片。

“面经消息”折叠区在 user 模式显示未读计数，每约 30 秒读取本地收件箱。支持查看正文、打开来源、标记已读及运行自检。当前展示最近 30 条，完整记录可分页通过接口读取；未实现外部机器人、邮件或系统弹窗。

## 采集边界与状态

只处理用户给出的单条链接，没有搜索、翻页、批量提交或订阅关键词发现新笔记的能力。每个订阅只检查同一条笔记的变化。没有真实链接时，不建立采集任务。

短链使用 iPhone Safari UA 展开，保留完整查询串。匿名 CookieJar 仅存在于一次采集调用中，不读取或持久化账号 Cookie；随后访问首页及带原查询串的 explore 页面。每次请求及跳转都校验 HTTPS、固定小红书域名与端口，并通过持久化请求门控制间隔至少 4 秒。单个采集最多六次请求，连接/读取超时 12 秒，调用预算约 90 秒，HTML 上限 4 MiB。预算在请求与分块读取之间检查，正在进行的 socket 操作仍受其超时约束。

状态对象使用字符串感知的括号计数；只在字符串外替换 undefined、NaN、空 Map/Set，不执行 JavaScript。支持提示词里的 noteData 路径及 noteDetailMap 路径，两者都只在本地合成页面上验证过。笔记 ID 必须严格匹配，正文为空不会成功；视频只返回 imageList 中的首张封面候选，不下载视频。

返回包括 `ok/reason/title/author/content/images`。成功收藏还包括本机 note_id、saved 和 source_url。reason：

- `success`：成功解析非空正文且 ID 一致。
- `no_post_id`：没有明确笔记 ID。
- `unreachable`：网络/超时失败，不表示链接失效。
- `need_login`：登录、验证或 HTTP 401/403；403 保守按访问受限处理，不能据此断言账号状态。
- `id_mismatch`：平台返回的笔记与请求不同。
- `invalid_url`：域名、协议、端口等不符合单条链接边界。
- `parse_error`、`empty_content`：解析失败或没有正文。
- `rate_limited`、`not_found`：HTTP 429 或 404/410。
- `collector_busy`：本机正在执行另一次采集，没有额外发请求。

不登录、不破解签名、不模拟设备指纹、不绕过验证。页面结构和平台可访问性无法由本地自检保证；匿名访问仍可能受平台服务条款限制。仅用于个人收藏，并保留来源。

## 调度、持久化与恢复

每个 owner 的独立 SQLite 文件位于个人 Career 根目录，文件名为 `note-subscriptions-<owner哈希>.sqlite3`。生产启动器对应被忽略的 `web/data/user/career-agent/`。其中保存订阅、下次执行时间、租约、运行历史、正文版本、通知及已读回执；没有修改既有面试/简历数据库结构。

FastAPI lifespan 启动后台任务并在退出时停止。每两秒检查一次，每轮最多处理一个到期订阅；同进程手动收藏与调度串行。SQLite `BEGIN IMMEDIATE` 原子抢占 180 秒租约，过期租约可恢复；每次提交重新核对租约编号、有效期与启用状态，暂停或过期执行的迟到结果不能落库。

笔记版本去重、收件箱消息与任务完成状态在同一事务提交。消息写入失败则整体回滚，重启后可重做；这保证本地通知与收藏一致，不声称外部网络消息能恰好送达一次。

网络失败按失败次数指数退避，上限七天，且不短于订阅周期。首次失败写一条告警，持续失败不刷屏。登录/验证、ID 不符、非法链接、缺少 ID 和 HTTP 不存在立即暂停；解析/空正文/本地执行连续失败三次暂停。暂停告警进入收件箱，显式恢复后重新检查。进程正常退出打断请求时不计失败。

应用关闭或电脑休眠时不运行。恢复后合并错过的周期，只检查一次，然后从完成时间计算下一次，避免补跑请求洪峰。这是固定间隔检查，尚未实现“每天北京时间某个时刻”、Windows 开机启动或服务守护。

回退方式：暂停相关订阅即可停止后续请求；已发出的请求无法撤回，迟到结果会丢弃。停止服务后可以完整备份上述 SQLite 文件，恢复时放回同一个 owner 的原路径；不要只复制正在写入的文件，也不要删除既有职业资料数据库。备份恢复演练、磁盘保留/清理策略和应用关闭后的独立监测尚未实现。

## 自检与验证

自检执行 SQLite quick_check、可回滚的写探针、固定合成页面解析、调度心跳、过期租约和超期任务统计；数据库不可写/损坏返回失败。`external_site_verified=false` 明确表示自检没有访问真实平台。用户可看到暂停数；关闭的订阅本身不使全局健康失败。调度错误会保留，直到下一次实际任务成功处理。

同源接口前缀 `/api/career-user/notes`，需 `mode=user`；私人引擎前缀 `/v1/notes`，继承服务 Bearer 鉴权：

- `POST /collect`：`{url}`。
- `GET/POST /subscriptions`：创建为 `{url, interval_hours?, keywords?}`。
- `POST /subscriptions/{id}/pause`、`/resume`。
- `GET /subscriptions/{id}/runs?limit=30`：最近执行记录。
- `GET /inbox?limit=30&offset=0`、`POST /inbox/{id}/read`。
- `GET /items/{id}`：正文、图片地址与来源。
- `GET /self-check`：健康明细。

2026-11-17 已完成确定性测试及隔离的真实 localhost HTTP、浏览器收件箱/正文/已读/自检与 390px 布局检查；采集传输使用合成响应。没有真实小红书链接，因此尚无实站成功率或长时间运行证据。验证输出位于工作区 `outputs/note-subscriptions-20261117/`。

后续更有价值的方向：用用户授权的 RSS、邮件或允许访问的公开数据源发现新面经，再由统一收件箱去重；为长期运行添加独立服务守护与磁盘监测。面经应作为外部参考材料保存，不得自动变成用户本人的经历，也不应未经确认直接当作模拟面试评分事实。
