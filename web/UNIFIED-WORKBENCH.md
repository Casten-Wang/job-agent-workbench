# 统一求职工作台

工作台默认显示下一步、常用任务、进行中任务、待确认事项和最近成果。沿用远程主线的单一“我的资料”数据集，历史本机记录继续保留。侧栏入口和全部工具都在同一工作台中打开原业务节点，保留原 DOM 标识、事件和表单状态。

主区承载操作与结果，侧边承载现有 Agent 会话。窄屏使用“对话助手 / 返回操作区”切换。普通表单草稿在当前浏览器会话中在本机浏览器会话中暂存；密钥、风险确认、事实确认和文件内容不写入草稿存储。刷新后，文件需要重新选择，确认选项需要重新核对。

## 接口

- `GET /api/workbench/overview?mode=user`：只读聚合能力目录、建议下一步、任务、待确认内容、成果和连接状态。模型服务不可用时，相关计数为 `null` 并标记 `partial`，不会以零冒充空资料，也不会启动采集或同步发送状态。
- `GET /api/workbench/settings?mode=...`：只返回模型名称、是否配置、是否待应用和能否配置，不返回密钥。
- 模型配置统一使用“设置 → AI 接口设置”的 `save-ai-settings`、`test-ai-connection` 接口；`POST /api/workbench/settings` 不再接受第二份密钥。运行任务结束后应用设置页中的更新，不重启工作台或删除会话。
- `POST /api/workbench/actions?mode=...`：正文 `{tool,arguments,operation_id}`。仅接受 `interview_agent/workbench_catalog.py` 中命名能力和其确定性参数校验。用于业务表单及受限 Agent 适配器，不接受任意 URL、脚本、SQL 或通用业务动作执行器。
- `POST /api/workbench/confirmed-action?mode=...`：复用既有个人资料、岗位审核、采集启动、文案同步和发送确认。模型不能调用此接口或生成批准决定。
- `POST /api/workbench/delivery-preview?mode=user`：正文 `{ids}`，返回实际发送文案及绑定指纹。确认时重新读取岗位、审批、文案和资料，变化后旧确认失效。
- 原会话接口新增 `POST /api/workbench-agent/conversations/{id}/context?mode=...`，只更新明确选择的岗位、已确认材料、简历版本及面试会话，不调用模型。原 messages 字段继续兼容，并可携带新增对象引用。

内部业务桥接只接受个人引擎令牌，地址与业务适配器固定；网页不能提供 owner、source 或令牌。网页设置及业务写入额外检查同源 Origin。

## 业务联动

自然语言可调用岗位、HR 回复、题单、文字面试、版本面试、项目资料检索、面经收藏订阅、变体、导出等命名工具。文件选择、账号授权、GitHub 项目贡献核对及最终发送继续通过具体表单完成。平台采集只准备带参数的启动表单，不代填风险确认。找岗位默认搜索已有岗位。

面经分享链接保存在本机，会话仅把链接引用交给模型；工具执行时再解析到用户提供的原链接。收藏和订阅仍只针对单条笔记，不代表关键词发现新笔记。信息推送仍为载荷预览。

申请草稿保留原修订和证据绑定。用户核对 Agent 招呼语后，可将其同步为已关联平台岗位的发送文案，再进入原发送复核。同步不发送；手动录入且未关联平台的岗位提供复制和人工申请路径。

进行中的文字、项目和简历版本面试显示在首页任务中，读取原模块权威状态。已结束的项目或版本面试进入最近成果，打开后恢复原会话和已保存复盘，不重新生成或重放回答。

写入回执保存在个人数据目录的 `workbench-operations.db`。相同操作编号和内容返回原结果；变更内容返回冲突。已提交但结果不明的操作不会自动重放。提交中的业务操作等待真实结果，停止不能撤销已完成的保存或发送。旧五列回执表只追加工具名称列，已有回执继续有效。

## 任务式外壳

默认界面按集成工作台概念稿（W01–W06）组织，原编号导航在任务外壳启用时隐藏（`body.wb-task-shell`）。业务节点仍是原 DOM，只是就地搬进当前任务区，离开时放回原位置；id、事件、表单值和后端接口不变。

- 左侧任务栏：新任务、最近任务（Agent 会话与进行中的面试）、底部「我的资料 / 全部功能 / 设置」与回退链接。
- 主区顶部：上下文条（目标岗位、简历版本、已确认经历，「更改」展开选择）和四步步骤条。能力到步骤的对应写在 `workbench.js` 的 `STEP_FOR`；资料、面经、设置、数据、统计等没有步骤，从底部入口或「全部功能」打开。
- W01 开始任务：目标输入框把文字交给 Agent 会话；四个意图按钮直接打开对应步骤；右侧列出可用资料与连接状态。
- W02 寻找岗位：已有岗位单选表格与岗位要点；「粘贴 JD / 导入 JSON」与「平台采集」借用原表单和采集面板。选择岗位只写入会话上下文，不会开始投递。
- W03 准备材料：最新简历与招呼语草稿在步骤内显示，页签为简历、招呼语、资料依据。选中正文可预填一条修改请求到任务对话；修改仍由 Agent 生成新修订并保留来源，界面不直接改写草稿。保存正式版本沿用原审批。
- W04 复核申请：原发送复核面板就地显示。除原有风险确认与预览绑定外，另需勾选「我已核对对象与内容」并输入「确认发送」，按钮才可用；这是额外条件，不替代原确认。
- W05 模拟面试：沿用任务上下文预填综合面试的岗位与简历版本（不覆盖已选值）。面试进行中（`#ci-stage` 可见）收起通用任务对话，只保留面试官一条对话；用户可手动展开。
- W06 HR 消息：步骤为整理消息、起草回复、确认发送、准备面试。回复确认面板在会话下方就地显示，原风险确认保留。

## 启动与回退

继续使用 `run_career_demo.ps1`，默认加载仓库内的 `interview_agent/`、`interview_hub/` 与 `github_source/`。无模型密钥时也会启动工作台、项目资料与面经服务；进入“连接与设置 → 打开 AI 接口设置”后启用模型。工作台、Agent 和综合面试共用设置页中保存的服务商、模型、地址与密钥，不读取环境变量或旧模型凭据文件作为备用来源。凭据沿用远端的独立存储，不进入 YAML 配置。

访问 `/?workbench=legacy` 可切回原工作台，页面提供返回统一工作台的链接。切换前保存尚未提交的表单。回退只切换界面，不删除业务记录或回执。

## 验证

主仓库和引擎测试分别覆盖 HTTP 契约、适配器、同源校验、回执、旧模式请求拒绝与上下文隔离、无密钥启动、配置延后应用、对象绑定及分页。`验证/unified_workbench_smoke.py --verify` 使用隔离数据库和本机发送接收端；`--live --verify` 只将合成资料交给真实模型。结果写入上级 `outputs/unified-workbench/`，不把协议模型通过等同于真实模型质量验证。
