# Web 工作台设计记录

这份记录对应「最终形态应该是一个网页」的补充要求。网页是本地离线工具层的唯一操作界面：数据存在项目目录 `web/data/`，后端只监听 `127.0.0.1`；OfferPilot 已内嵌为同进程后端，工作台自身不接入其他外部 API，不读取真实邮箱/飞书，不自动投递。

## 设计计划

### 颜色

视觉语言复用队友项目 [offer_coming](https://github.com/lwt20000321-cmd/offer_coming) 的轻盈画布、粉蓝环境光、圆角卡片与药丸控件；只移植视觉，不引入 React/Vite 或任何远程资源。

| 角色 | Light | Dark | 用途 |
|---|---|---|---|
| 页面底色 | `#ffffff` | `#0b0b0d` | 整体画布 |
| 图表面 / 面板 | `rgba(255,255,255,.86)` | `rgba(21,21,24,.88)` | 数据面板与左侧栏 |
| 主墨色 | `#0a0a0a` | `#f5f5f7` | 正文、数字、主按钮 |
| 次墨色 | `#3f3f46` | `#b4b4bb` | 次级正文 |
| 说明文字 | `#71717a` | `#8e8e96` | 注释、标签 |
| 结构线 | `rgba(10,10,10,.08)` | `rgba(255,255,255,.1)` | 1px 分隔 |
| 强调粉 | `#e4889c` | `#e4889c` | 流程序号、环境光、已接入状态 |
| 数据 1 / 2 / 3 | `#0a0a0a` / `#e4889c` / `#8aa4ff` | `#f5f5f7` / `#e4889c` / `#8aa4ff` | 渠道与季度计数；始终有数据表兜底 |

9 状态工序带使用 5 档粉色阶（`#f5d0d8 → #efb3c1 → #e4889c → #c96b80 → #a44d62`），只表达阶段深浅，不作为精确数值编码；精确计数始终以节点数字和数据表为准。状态色（good/warning/bad/neutral）只用于带文字的状态徽标。

配色校验实际运行过 `validate_palette.js`：三色分类色在 light/dark 表面、`--pairs all` 下通过；蓝色阶段色阶在 light/dark 表面、`--ordinal` 下通过。Light 第 3 色的对比度 WARN 由直接数值标签与每个图的表格视图兜底。

### 字体

中文优先的系统无衬线：`"PingFang SC", "Source Han Sans SC", "Noto Sans SC", -apple-system, BlinkMacSystemFont, "Microsoft YaHei", system-ui, sans-serif`。标题收紧字距，正文保持 1.5–1.6 行高；数字表格与坐标轴使用 `font-variant-numeric: tabular-nums`。不加载远程字体。

### 布局

核心概念是「左侧流程索引 + 主工作台」。左侧栏固定九个入口，分为三组：核心流程 01–04（工作台、找岗位、审批队列、HR 回复）、成长工具 05–08（个人资料、模拟面试、信息推送、定制简历）、系统 09（数据与设置）；数据模式与外观固定在栏底。02 找岗位是一个二级入口，页内用胶囊页签在「采集岗位」与「岗位池」之间切换，不再让采集参数藏在岗位池里。

「采集岗位」是一条纵向主线：① 搜索表单（关键词、城市、页数、采集节奏、评分简历上传、自动评分，只作用于本次任务，不写回 `config.yaml`；简历本身写入本机运行时目录）→ ② 启动前检查（浏览器运行时、Chrome 调试端口、BOSS 标签页）→ ③ 任务状态 → ④ 采集结果。启动前必须同时满足预检通过与双勾选；页面用「会 / 不会」两栏说明采集边界，没有投递入口。任务完成后自动导入岗位池并跳到岗位表，失败时保留「导入全部到岗位池」重试入口。表单里的「评分简历」可直接上传 `.md` / `.docx` / `.pdf`（最大 5 MB，只存本机运行时目录）；有简历且 AI 已配置时「采集后自动评分」默认勾选，没有简历不阻塞采集，岗位以「未评分」导入。

审批队列分「待确认」与「已确认」两段：待确认段需要输入确认语；已确认段可勾选岗位生成招呼语，结果以只读卡片预览。复核后点「复核并发送」，输入「确认发送本批 N 条」并勾选风险确认，才会启动发送；每批最多 10 条。发送由内嵌运行时执行，沿用发送窗口、每日上限、随机间隔与风控锁，结果按岗位回写为已发送 / 失败 / 延后 / 已阻止。编辑招呼语、失败重试与定时批次仍按 [AUTO-DELIVERY-DESIGN.md](AUTO-DELIVERY-DESIGN.md) 的后续阶段实现。

「岗位池」以岗位表为第一屏，手动录入 JD 与高级静态 JSON 导入收在表格之后的折叠区。勾选一个或多个岗位后点「加入审批队列」，也可用行内按钮单独加入；低于 4.0 评分门或未评分的岗位需要连点两次确认才手动入队（`manual_override`），共享评分门本身不变。主工作台第一屏是六段核心流程，其后才是 9 状态工序带、KPI、图表与最近动作，并提供去采集、看岗位池、看审批队列的快捷入口。个人资料是软前置事实源，含完整度进度条、事实确认与可增删的教育/工作/项目卡片；未填写不阻塞其他页面。

```text

┌──────────────┬───────────────────────────────────────────────┐
│ 品牌          │ 标题 / 刷新 / 状态行                            │
│ 核心流程 01–04│ 统一筛选行（时间 → 渠道 → 状态）                │
│ 成长工具 05–08│ ┌── 六段核心流程（采集→评分→确认→招呼→发送→监控）┐│

[品牌 + 两行药丸导航 + 设置区]
```

所有面板左对齐，标题不居中；表格横向滚动只在窄屏出现。图表上方只有唯一一行筛选控件，所有 KPI、图表、表格和活动都按同一份筛选结果重绘；这行筛选只属于工作台，切到采集、岗位池、审批等入口时隐藏，避免无关控件占据首屏。刷新时保留上一帧并降低透明度，不使用骨架屏。

### 原则

1. 六段核心流程是第一记忆点；9 状态工序带是第二记忆点，其余区域保持安静。
2. 01–09 只表示左侧导航顺序；流程节点与 9 状态带的编号都对应真实有序结构，不做无意义装饰。
3. 所有外部输入（JD、邮件、逐字稿、PDF 文本）按数据展示；页面用 `textContent`，不拼 `innerHTML`。
4. 每个有图的地方都有表格视图；hover/focus 提示只增强，不成为唯一读数方式。
5. 人工确认动作使用明确的动词：「加入审批队列」「确认可人工投递」「生成话术草稿」；界面不出现「一键投递」「提交申请」。
6. 深色模式是显式选择的一套色值，同时给系统偏好和使用者切换留了覆盖关系，不是自动反色。
7. 发送与 HR 回复监控没有工作台自己的执行路径；发送只能走内嵌 OfferPilot 既有的人工确认流程，外部 Agent 只能通过 `POST /api/pipeline/event` 回报，界面显示「待接入 / 已接入回报」，不显示为已自动投递。
8. 内嵌后端不可用（依赖缺失或初始化失败）时，面板显示「未就绪」与本地安装提示，页面其余部分照常离线工作；不把不可用状态画成已连接。

## 对通用模板的复核与修订

- 早期版本是「控制桌」式的零圆角、无阴影、青绿色界面；对照队友项目后改为更轻盈的白底、粉蓝环境光、28px 圆角面板与药丸导航，信息结构不变。
- 保留完整中文句子和真实状态名，不采用顶部全大写 eyebrow、卡点式 meta 串或按钮后附箭头。
- 首屏不放大数字 hero；先放六段核心流程，再放 9 状态路径带，因为主任务是看清整条链路和每份岗位停在哪一步。
- 圆角与阴影只用于面板、卡片和控件，不改变表格密度、筛选逻辑或任何安全边界。
- 季度雷达 JSON 的 8 个轴混合了计数与弱点标记，不画成一张雷达图；拆成同量纲的分组柱图、单系列弱点图和原始 JSON 表，避免双轴或隐含比例。

## 可访问性与边界

- 键盘焦点有 2px 可见描边；`prefers-reduced-motion` 关闭过渡；`role="status"` 和 `aria-live` 汇报操作结果。
- 图表 2 个以上系列有图例，3 个系列有选择性直接标签；单系列不画图例；分类色按固定顺序，不循环生成。
- 所有静态资源本地加载，CSP 禁止外部脚本、样式、iframe 和对象；服务端只绑定 loopback。
- 网页提供输入、解析、审批、状态、去重、ICS 下载、Mock、复盘、测试、报告与导出；平台采集与浏览器自动化由内嵌 OfferPilot 执行，但投递仍须人工确认。真实 IMAP/飞书 HTTP、ASR 运行保持未实现，不把 dry-run 写成真实接入成功。
- 审批通过后的受控投递（生成 → 复核 → 发送 → 回报）目前只有设计提案：[AUTO-DELIVERY-DESIGN.md](AUTO-DELIVERY-DESIGN.md)，代码尚未实现，界面与接口都不存在。
